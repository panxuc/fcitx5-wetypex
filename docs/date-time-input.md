# 日期、时间候选

WeTypeX 使用原版输入核心生成当前日期和时间的候选，格式与原版一致。

## 使用

| 输入方式 | 日期 | 时间 |
| --- | --- | --- |
| 中文全拼 | `riqi`、`rq`、`date` | `shijian`、`sj`、`time` |
| 中文全拼 V 入口 | `vriqi`、`vrq`、`vdate` | `vshijian`、`vsj`、`vtime` |
| 双拼 | 所选方案中“日期”的编码 | 所选方案中“时间”的编码 |
| 五笔 | “日期”的字形编码 | “时间”的字形编码 |

普通编码的首选保留原版普通词，日期或时间格式从第二项开始：按空格输入“日期”“时间”等普通词，按 `2` 选择第一种格式，其他格式用数字或翻页选择。V 入口以格式为首选，按空格直接选择第一种格式，Enter 保留字面编码。在任何入口中，Enter 按原编码上屏，Esc 取消。英文模式中的字母照常直接输入。

| 类别 | 格式 |
| --- | --- |
| 日期（七种） | 年月日、连字符、斜杠、点分隔、紧凑数字、中文数字、农历 |
| 时间（四种） | 三种带日期的时间和一种纯时间 |

选中的格式按原文提交，自动添加中英文空格不会改写其内部格式。

日期和时间使用系统时区，显式设置的 `TZ` 优先。每次重新输入都会刷新时间；选词提交的是屏幕上那次候选的值。

## 实现

原版核心通过 `Calendar::Impl::MatchWord`、`TimeFormat::FormatAllDate`、`TimeFormat::FormatAllTime` 和农历转换函数生成这些候选。日历匹配适用于拼音、双拼和五笔，因此双拼与五笔的触发编码由原版核心按候选词匹配，前端不硬编码全拼字符串；会话配置 `+0x127` 控制额外的英文 `date` / `time` 入口。

原版 C 接口中，候选结构 `+0x30` 指向附加信息链表。`NewAndCopyCandidateInfoToCStruct` 把 `TimeFormatInfo` 转为类型 9 的节点：类型位于 `+0`，下一节点 `+8`，UTF-8 文本 `+16`，字节长度 `+24`。每种格式占一个节点，基础候选本身可能只写“日期”或“时间”。这些偏移属于兼容档案的 `mac-capi-v1` ABI，最初依据 macOS 2.2.3.657 确认。Windows 3.0.2.22 安装包的 `libwxhld.dll` 同样包含 `TimeFormatInfo`、`CalendarCandidateID`、`TimeFormatProfile<64>`、`TimeFormatType`、`riqi` 和 `shijian`，说明两个平台使用同一类原版核心能力。

Linux 宿主复制附加信息中的格式文本，保留原版候选 ID、覆盖长度和选词调用。普通编码把第一个原版普通候选放回首位，其后保留整组格式与其余候选；V 入口继续以格式为首选。系统 `/etc/localtime` 以只读方式挂载进后端沙箱。生成这些候选不需要额外的日历库，也不为每次输入另开后端会话。

## 验证

通过真实原版后端 IPC 验证了候选生成、逐项选择、普通候选、原编码提交、退格清空、过期候选拒绝、时间快照和再次输入刷新，并在真实 Fcitx5 与 Wayland 编辑器中核对了键盘选词。
