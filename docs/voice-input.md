# 流式语音输入

语音使用官方 2.2.3.657 包内的 `voice_engine_*` C 接口。录音接口采集 16 kHz、单声道、16 位 PCM，随后交给原版引擎完成 Opus 编码、VAD、分包、重试、中间结果和最终结果处理。录音期间持续识别，停止后沿用原版的最终结果与智能整理流程。

识别、编码和语音检测使用原版实现；输入框预编辑、状态面板和音频设备接入由 Fcitx5、PipeWire/PulseAudio 提供。

## 操作

- 按住说话快捷键开始录音，松开结束。
- 切换式语音快捷键开始录音，再按一次结束。按住模式中按切换式快捷键会转为持续录音。
- 空格结束录音；Enter 提交当前已识别结果；Esc 取消。
- 输入其他字符时取消语音，并正常处理该字符或应用快捷键。
- 离开输入框、切换输入法、重置上下文或重新加载配置时取消语音。迟到的结果不会写入另一个输入框。

中间结果显示为预编辑，最终文本只提交一次。显示位置遵循外观中的“拼音显示位置”；输入框不支持内嵌预编辑时，使用 Fcitx 候选面板。启动语音前若还有未完成拼音，会先提交原始拼写，保留已经输入的内容。

快捷键可在设置中修改。普通按键形式的快捷键也支持按住使用，自动重复不会反复启动或取消录音。默认组合键见[配置参考](configuration.md)。

识别完成后，最终文本在提交给输入框的同时写入系统剪贴板（“语音输入 → 识别后复制到剪贴板”，默认开启，JSON 字段 `voice_copy_to_clipboard`）。Wayland 通过 `wl-copy` 以 data-control 协议持有选择，不需要窗口或焦点；缺少 `wl-copy` 时使用剪贴板助手。终端等只处理按键事件的窗口可能丢弃提交文本，此时可以直接粘贴。

## 原版语音资源

正常准备运行时会同时提取原版 VAD 配置和模型，保存到用户数据目录的 `fcitx5-wetypex/voice/vad/`。已有运行时可仅更新资源：

```bash
fcitx5-wetypex-setup --archive /path/to/WeType_2.2.3_657.zip --icons-only
```

该操作也更新界面图标和微信表情字体。缺少 VAD 文件时仍可手动结束语音；补齐资源后才能使用原版的本地语音检测。原图、模型和原版二进制均不随 WeTypeX 发行。

## 设备与诊断

在设置中选择麦克风，或使用“自动检测”采集默认输入源。录音通过内存管道传递，不再先保存整段 WAV、等待录完后转码。单机模式下快捷键不启动语音。

现代 `pw-record` 支持 `--raw`，且实际 PipeWire 服务具有音源时，直接使用 PipeWire；只安装工具、仅运行屏幕共享服务或 Ubuntu 22.04 等旧版本时，自动选择 `parec`，缺少该工具时回退到 FFmpeg 的 PulseAudio 输入。PulseAudio 客户端也支持 pipewire-pulse，已有系统可沿用现有音频服务。录音仍通过内存管道交给原版引擎，不保存整段音频文件。

设置页同时支持枚举旧版 PulseAudio 麦克风。已选设备断开后会显示“当前不可用”，可重新选择设备或“自动检测”。明确指定 PipeWire 设备时不会改录默认麦克风；采集连续 5 秒没有返回音频时会结束并提示检查设备和音频服务。静音设备仍会返回静音音频，不受这项超时影响。

音频后端变化时，旧的数字设备编号不会被当成另一个后端的同编号设备；需要在设置中重新选择麦克风，或改用“自动检测”。

查看本地语音状态：

```bash
fcitx5-wetypex-voice status
```

`native_ready` 表示原版语音宿主已启动，宿主运行时的 `vad` 表示原版模型已加载；空闲释放宿主后，两者均为 `false`。`capture_backend` 标明使用的录音接口：`pipewire`、`pulse` 或 `ffmpeg-pulse`，已有音频文件转写时为 `file`；`capture_pid` 仅在音频采集进程运行时有值。`timings` 记录采集启动、首个文字结果和停止到最终结果的时间，便于区分设备、建连和识别延迟。

也可以转写已有音频文件。此命令会连接原版语音服务：

```bash
fcitx5-wetypex-voice transcribe /path/to/recording.wav
```

添加 `--realtime --verbose` 可按音频实际时长送入并查看中间状态。原来的 `fcitx5-wetypex-account voice-file recording.opus` 也使用同一引擎。

日志位于用户状态目录的 `voice/capture.log`、`voice/backend.log` 和 `voice/daemon.log`。状态与日志保存在私有目录中，可能含有识别文本或账户标识；分享排查信息时提供状态、时间字段和脱敏错误即可。

## 会话与资源管理

轻量控制服务在输入法激活时准备，通过同用户的 Unix socket 接收快捷键命令，避免每次停止录音都等待 Python 进程启动。语音结果在录音期间每 40 ms 检查一次，独立于设备同步的节拍。

原版宿主使用独立的语音业务缓存和账户身份快照，录音不会长时间占用设备同步使用的账户锁。主账户切换或退出时，下一次语音会重建对应缓存。原版宿主空闲两分钟后释放；轻量控制服务在空闲十分钟后退出。

会话以输入上下文、epoch 和唯一 token 关联。取消、快速松键、控制进程退出或宿主故障都会结束采集；旧会话的中间结果和最终结果会被丢弃。

升级录音辅助程序后，可执行 `fcitx5-wetypex-voice shutdown` 结束旧控制服务；下次启动语音时会运行新版本。
