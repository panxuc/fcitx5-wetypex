# 架构说明

## 目标

WeTypeX 将原版桌面输入核心接入 Fcitx5，同时让 Linux 桌面负责输入上下文、进程隔离、音频、剪贴板和界面。设计目标是保留真实候选、账户和联网服务结果，并避免为了输入法启动完整 Wine 或虚拟机。

支持范围固定为 Linux x86-64 与原版 macOS 2.2.3.657。原版程序不是普通 Linux 动态库，因此设置过程会校验官方压缩包、提取核心与词典，并生成可由兼容宿主加载的映像和重定位清单。

## 运行组件

| 组件 | 职责 |
| --- | --- |
| `wetypex.so` | Fcitx5 输入法引擎、按键状态、候选、预编辑和提交 |
| `wetypex-engine-host` | 加载固定版本原版核心，提供所需 Darwin ABI |
| `wcwss_bridge.so` | 将原版网络调用桥接到 Linux curl/TLS/WebSocket |
| `fcitx5-wetypex-backend` | 在 Bubblewrap 中启动持久输入服务 |
| `fcitx5-wetypex-account` | 执行配对、设备组、同步、语音和传输业务请求 |
| `fcitx5-wetypex-syncd` | 轮询设备组并交换剪贴板内容 |
| `fcitx5-wetypex-transfer` | 生成官方二维码、发布临时 CA 与连接角色，并驱动原版 Flurry LAN/WXP2P 文件通道 |
| `fcitx5-wetypex-settings` | 独立设置窗口，与 Fcitx5 配置页共用配置 |
| `libwetypexconfig.so` | Fcitx5 Qt6 配置页中的完整设置、账号与同步入口 |
| `fcitx5-wetypex-ai` | 调用原版 AI 服务并打开问答窗口 |
| `fcitx5-wetypex-voice` | PipeWire 录音、Opus 编码和识别结果投递 |

## 输入路径

每个 Fcitx5 `InputContext` 都拥有独立会话、序号、epoch、候选修订号和本地模式状态。插件通过一行一个 JSON 对象的私有管道向后端发送按键。后端把输入交给原版会话，返回预编辑、候选和提交文本。

候选选择携带修订号，防止异步云候选到达后误选旧列表。插件只在目标应用中设置 client preedit；候选窗口不重复显示拼音。密码上下文直接绕过后端；浏览器标记为敏感的普通输入仍可使用输入法。

## 原版兼容边界

兼容宿主只初始化原版 C/C++ 输入和业务区域，不运行 AppKit、Swift 设置窗口或官方桌面进程。宿主提供实际被使用的线程、文件、时间、区域设置、CoreFoundation 轻量对象和 libc++ ABI，并对未实现导入使用受控陷阱。

所有固定地址、结构尺寸和字段偏移都绑定于受支持的原版版本。设置工具同时校验压缩包和核心散列，避免用错误版本进入未定义行为。

## 网络与账户

账户身份由原版业务层生成并保存在 `account/identity.json`。六位匹配码、确认绑定、设备组和功能位都调用原版业务服务；项目不生成假账户，也不模拟成功结果。

输入后端仅在未开启单机模式且存在设备身份时联网。账户命令使用独立文件锁，防止多个原版业务上下文同时修改加密状态。

## 同步

设备组返回的功能位映射如下：

- `0x1`：跨设备剪贴板。
- `0x2`：常用语同步。
- `0x4`：个人词库同步。

文字剪贴板使用原版文本消息；PNG 图片使用 `TypeImageOri` 和二进制字段。Wayland 优先使用 `wl-copy` / `wl-paste`，X11 使用 Qt 剪贴板。同步守护进程是唯一的系统剪贴板写入与上传端：它像原版 Windows/macOS 客户端一样维护设备组内的单调版本游标，并在查询设备组时上送当前版本。远端消息只有在版本更新、来源不是本机且尚未过期时才写入；本机上传成功后立即前移同一个版本游标，从而避免旧内容回传和多写入者竞态。

## 语音与 AI

语音由 `pw-record` 采集为 16 kHz 单声道 PCM，再由 FFmpeg 编码为 Opus。兼容层转换为原版 `#!OPUS_RAW_V1` 流并按原版序号、累计字节数和结束标志发送。结果经私有 inbox 回填当前聚焦输入框。

AI 使用目标应用的 surrounding text 作为问题。原版服务返回服务器渲染的 HTML；Linux 窗口移除依赖 `WKWebView` 消息桥的渐显脚本，保留正文和 Markdown 样式。窗口通用图标由设置工具从官方包提取，不随仓库发布。

## 隔空传送

传输窗口先同时预加载原版 Flurry 与 WXP2P 动态库，再调用 Flurry 生成会话 CA。二维码发起端向官方业务服务提交 CA、`preferred_client=false` 的角色信息、局域网地址、设备名和功能位；iOS/Android 扫码端以 `preferred_client=true` 加入。官方服务返回双方各自的 `dispatch_buf` 后，桌面端立即把未经改写的调度数据交给 `FlurryWXP2P`。

发现扫码设备后，桌面端同时使用对端 CA 启动 Flurry LAN 服务端，生成包含随机端口与服务名的 `GrpcNetInfo` JSON，并通过第二次 Join 请求更新本端信息。这一阶段与移动端实现一致；双方会优先采用可用的局域网通道，并保留 WXP2P 的公网打洞和腾讯中继作为备用。

文件分片、应用层 ACK、校验、重名处理和进度均由原版 Flurry 实现。Linux 兼容宿主负责 Darwin 套接字、kqueue、线程、时间和文件 ABI；跨文件系统落盘使用同目标目录内的临时文件完成原子复制，再删除分片。连接失败后仍继续轮询同一传输码，手机重试产生新调度数据时会重建传输会话。

## 沙箱与文件权限

输入和账户宿主运行在 Bubblewrap 容器中，只读绑定系统库、证书与已准备运行时，可写目录限于对应状态目录。离线模式额外隔离网络命名空间。账户、AI、语音和剪贴板状态使用 `0700` 目录与 `0600` 文件。

WeTypeX 不把用户文本发送到自建服务器。启用云候选、同步、语音或 AI 时，相关内容会进入原版腾讯服务；单机模式关闭这些联网能力。
