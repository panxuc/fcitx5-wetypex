# 架构说明

WeTypeX 把微信输入法 macOS 版的原版 C/C++ 输入核心接入 Fcitx5。Linux 桌面负责输入上下文、进程隔离、音频、剪贴板和界面；原版核心负责候选、词库、账户和联网服务的实际结果。整个方案在原生 Linux 进程中运行，无需 Wine 或虚拟机。

## 适配层与原版运行时

| | 适配层 | 原版运行时 |
| --- | --- | --- |
| 来源 | 本仓库源码，MIT 许可 | 微信输入法官方下载服务，专有 |
| 安装 | 包管理器或 Nix，位于 `/usr` 或 Nix store | `fcitx5-wetypex-setup`，位于用户数据目录 |
| 内容 | 插件、兼容宿主、设置界面、辅助命令、兼容清单 | 输入核心、词典、Flurry/WXP2P 传输模块、界面与语音资源 |

原版程序是 macOS Mach-O 映像。设置工具校验官方 ZIP 与组件散列，为本机架构（x86-64 或 ARM64）提取对应切片和词典，并生成兼容宿主可加载的映像与重定位清单。可接受的版本和组件组合由兼容清单 `runtime-profiles.json` 决定，见[运行时更新、回退与清理](runtime-updates.md)。

## 输入路径

每个 Fcitx5 `InputContext` 拥有独立的会话、序号、epoch、候选修订号和本地模式状态。插件通过私有管道向后端发送每行一个 JSON 对象的请求，后端把按键交给原版会话，返回预编辑、候选和提交文本。

核心回调通过 eventfd 唤醒同一服务线程，由该线程生成异步状态快照，使输入操作与输出保持串行顺序。快照携带会话、epoch、当前请求序号和单调更新号，提交文本只发出一次；前端丢弃旧序号、旧 epoch 和重复更新。前后端通过 `candidate_updates` 能力协商云候选推送：支持推送时前端无需轮询，旧版后端继续使用轮询，旧版插件也不会收到无法处理的推送。

首个候选窗口等待正在处理的本地输入回复，回复到达即显示完整内容；超过约一帧时先显示预编辑兜底。内嵌预编辑、语音和 V 模式不经过这段等待。等待由现有主计时器以毫秒精度调度，取消、失焦和重置都会清除等待状态。

已显示的候选在选择时携带修订号，后端保留对应的候选 ID 快照，异步云候选更新不会改变选词结果。输入尚未返回候选时按空格或数字，选词请求排在这些输入之后，由后端处理完字母再选择对应候选。空格遇到没有候选的组合时提交原始输入。

支持且启用内嵌预编辑的客户端默认在目标应用中显示拼音；外观设置可改为始终在候选窗口显示，不支持内嵌预编辑的客户端自动使用候选窗口。没有组合输入时清空预编辑、辅助文本和候选列表；退出输入法后，迟到的后端响应不会恢复面板。密码输入框直接绕过后端；浏览器标记为敏感的普通输入框照常使用输入法。按键规则详见[按键与输入模式](input-handling.md)。

## 原版兼容边界

兼容宿主只初始化原版的 C/C++ 输入与业务部分，不运行 AppKit、Swift 设置窗口或官方桌面进程。宿主提供原版实际使用的线程、文件、时间、区域设置、CoreFoundation 轻量对象和 libc++ ABI，对未实现的导入符号使用受控陷阱。

固定地址、结构尺寸和字段偏移随兼容档案的 `abi` 标识绑定。设置工具在准备运行时时校验官方 ZIP、核心切片和词典散列，只有兼容清单中列出的组合才会被加载。

## CPU 指令集与兼容执行

x86-64 原版核心的硬件 AES 路径需要 AVX 和 AES-NI；缺少 AES-NI 时，原版的软件 AES 表初始化使用 AVX2。宿主会检查实际 CPU 和操作系统是否提供 AVX，并确认 AES-NI 或 AVX2 至少有一项可用。有 AES-NI 的老处理器可以继续原生执行；能力不足时使用 `qemu-x86_64` 执行同一份原版核心。ARM64 的指令集要求见 [ARM64 支持](arm64.md)。

默认执行方式为 `auto`。`WETYPE_ENGINE_PROVIDER=native` 强制原生运行，仅用于定位故障；`qemu` 强制兼容执行。`fcitx5-wetypex-account network-info` 中的 `native_cpu_supported` 表示原生能力，`execution_provider` 表示所选方式，`execution_ready` 表示该方式实际可用。

兼容执行前会让 QEMU 运行宿主自身的 CPU 检查，不加载原版核心。只有文件存在还不够：例如 Ubuntu 22.04 仓库中的 QEMU 6.2 无法提供这里需要的 x86 指令集，检查会提示升级组件。普通发行版通过 `qemu-user` 提供模拟器；Nix 用户设置 `enableCompatibilityProvider = true`，只构建当前架构的用户态模拟器。

## 运行时版本代

`runtime` 是指向当前版本代的符号链接。更新先在 `runtime-generations/` 中准备新版本代，再在空闲时原子切换链接。使用原版核心的进程（输入后端、账户命令、隔空传送、语音和 AI）在启动时取得共享的 `runtime-use.lock` 租约；切换需要独占租约，因此会等待这些进程结束。切换前写入事务日志，并保存用户数据快照；中断后的下一次操作先依据日志恢复。

## 网络与账户

账户身份由原版业务层生成并保存在 `account/identity.json`。六位匹配码、确认绑定、设备组和功能位都调用原版业务服务，WeTypeX 不生成假账户，也不模拟成功结果。

输入后端仅在单机模式关闭且存在设备身份时联网。账户命令使用独立文件锁，避免多个原版业务上下文同时修改加密状态。网络连接采用 Happy Eyeballs，并在网络或 TLS 建连失败时于同一超时预算内尝试 IPv4。

## 同步

设备组返回的功能位：

| 位 | 功能 |
| --- | --- |
| `0x1` | 跨设备剪贴板 |
| `0x2` | 常用语同步 |
| `0x4` | 个人词库同步 |

文字剪贴板使用原版文本消息，PNG 图片使用 `TypeImageOri` 和二进制字段。同步守护进程只在功能位 `0x1` 开启时访问本地剪贴板，启用时先建立本地基线。它是唯一的系统剪贴板写入与上传端，并像原版 Windows/macOS 客户端一样维护设备组内的单调版本游标：远端消息只有在版本更新、来源不是本机且尚未过期时才写入；本机上传成功后立即前移同一游标，从而避免旧内容回传和多写入者竞争。

Wayland 下，同步守护进程先通过剪贴板助手查询合成器公布的 data-control 协议，并核对 `wl-paste`/`wl-copy` 的版本。两者兼容时使用原生 Wayland，否则通过 Qt/XWayland 以无窗口方式读写，避免临时窗口抢走焦点。X11 使用 Qt 剪贴板。

## 语音与 AI

语音由 `pw-record` 以原始 PCM 采集；旧版 PipeWire 或缺少该工具时使用 `parec`，再回退到 FFmpeg 的 PulseAudio 输入，也兼容 pipewire-pulse。三条路径都流式输出 16 kHz、单声道、16 位 PCM，直接交给当前原版核心的 `voice_engine_*` 接口，由原版实现 Opus 编码、VAD、请求序号、重试、平滑结果和最终整理。中间结果通过私有 inbox 更新预编辑，最终结果只在同一会话、epoch、token 且仍有焦点时提交一次。控制通道是同用户的 Unix socket；语音业务缓存与设备同步分离，宿主空闲时释放。详见[流式语音输入](voice-input.md)。

AI 以目标应用的 surrounding text 作为问题。原版服务返回服务器渲染的 HTML；Linux 窗口移除依赖 `WKWebView` 消息桥的渐显脚本，保留正文和 Markdown 样式。窗口图标由设置工具从官方包提取，不随仓库发布。

## 隔空传送

传输窗口先预加载原版 Flurry 与 WXP2P 动态库，再调用 Flurry 生成会话 CA。二维码发起端向官方业务服务提交 CA、`preferred_client=false` 的角色信息、局域网地址、设备名和功能位；iOS/Android 扫码端以 `preferred_client=true` 加入。官方服务返回双方各自的 `dispatch_buf` 后，桌面端把未经改写的调度数据交给 `FlurryWXP2P`。

发现扫码设备后，桌面端用对端 CA 启动 Flurry 局域网服务端，生成包含随机端口与服务名的 `GrpcNetInfo` JSON，并通过第二次 Join 请求更新本端信息。双方优先使用可用的局域网通道，WXP2P 的公网打洞和腾讯中继作为备用。

文件分片、应用层 ACK、校验、重名处理和进度均由原版 Flurry 实现。兼容宿主提供 Darwin 套接字、kqueue、线程、时间和文件 ABI；跨文件系统落盘时在目标目录内用临时文件完成原子复制，再删除分片。连接失败后继续轮询同一传输码，手机重试产生新的调度数据时会重建传输会话。

## 沙箱与文件权限

输入和账户宿主运行在 Bubblewrap 容器中，只读绑定系统库（包括宿主 `/lib64`）、证书、时区和已准备的运行时，可写目录限于各自的状态目录。单机模式额外隔离网络命名空间。账户、AI、语音和剪贴板状态使用 `0700` 目录与 `0600` 文件。启动沙箱前清空环境并显式传入所需变量，兼容 Ubuntu 20.04 的 Bubblewrap 0.4。

## 数据流向

WeTypeX 不运营自己的服务器。开启云候选、同步、语音或问 AI 时，相关内容发送到原版腾讯服务；单机模式关闭这些联网能力。适配层更新器访问 GitHub Release，原版运行时更新访问微信输入法官方下载服务。
